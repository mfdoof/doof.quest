Hardening a static site on Cloudflare's free plan

After a scanner probed this site for credential files, I set up four layers on Cloudflare's free plan: a real 404 page, an allowlist, a challenge for cloud hosts and a rate limit.

$ cat goal

Stop scanners before they reach the site, without upkeep and without getting in the way of real visitors. The postmortem explains what started this.

$ cat design

  • 404 page. Pages returns a real 404 for missing paths, so there's nothing to find.
  • Allowlist rule. A custom WAF rule blocks any path that isn't part of the site: the homepage, about, resume, and the notes, projects and asset folders.
  • Cloud host challenge. Requests from big hosting providers get a Managed Challenge. Verified bots like search crawlers skip it.
  • Rate limit. An IP that asks for too many pages in ten seconds is blocked for a short time. Asset files don't count.
  • Bot Fight Mode is on as well.

$ cat decisions

  • Allowlist over blocklist. My first rule listed bad paths like .env and .git. Scanners change paths all the time, so that list would never be done. The site has a small, known set of paths, so listing those is easier and catches probes I haven't seen yet.
  • Challenge, not block, for cloud hosts. Some real people browse from those networks, like VPN users or someone on a work VPN. A challenge lets a person through in a second or two. Scripts can't pass it.
  • Leave crawlers alone. I almost included Google's own network in the list, which would have challenged Googlebot. The rule now skips verified bots, so search crawlers and link previews on LinkedIn or Slack still work.
  • Swapped a rule I didn't need. The free plan's one rate limiting rule came set up for leaked password checks. This site has no login, so I used the slot for bursts.

$ cat gotchas

  • Pages drops .html. /about.html redirects to /about, so the allowlist needs both.
  • New paths need adding. A new top-level page or folder gets a 403 until it's in the rule.
  • Free plan limits. One rate limiting rule, and the counting window and block time are fixed at ten seconds.

$ cat verify

The encoded .github paths from the earlier scan now get 403 as well.

$ cat lessons

  • Allowlists scale, blocklists don't. When the set of good paths is small, list those.
  • Think about who else a rule hits. Every rule has a cost for someone. Check that before deploying it.
  • The free plan is enough for a static site. The 404 page does most of the work. The rules keep the noise down.
